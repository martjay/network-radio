Fix recording continuity for both container and raw-frame streams

The previous fix handled Ogg/Opus but broke MP3, and the regression only
showed up because test_functional (which had been skipped) exercises the MP3
path. Two distinct faults were involved.

1. Dropped middle of the stream. The relay retains audio from before the
   recorder attaches so a recording does not start with silence. The buffer
   stopped appending once it hit its cap, which left a gap between the
   retained prefix and the resumed stream. Decoding progressively showed the
   first 6 seconds clean and the failure appearing later, at exactly the cap
   offset. The window now slides: once full the oldest bytes are dropped, so
   what remains is always contiguous with the live data that follows.

2. Header replay applied to the wrong formats. When the window has wrapped,
   the retained audio no longer begins at the stream header. Ogg needs that
   header page to initialise its demuxer, so it is replayed for container
   formats. MP3 and ADTS AAC are self-synchronising frame streams: replaying
   a byte prefix there duplicates audio and desynchronises frame boundaries,
   which is what produced "Header missing". The recorder now reports whether
   its detected format needs the header, and the relay honours that.

Format identification also reads the true stream start rather than the
sliding window, since a wrapped window begins mid-stream and would
misidentify the container.

The build pipeline gains a recording step: --rectest records a live station
and decodes the result, so a packaged build verifies the recorder the same
way it already verified playback. tools/test_frozen.py drives selftest,
playtest and rectest against the frozen exe for both an MP3 and the
Ogg/Opus station.

Verified: 10 test suites pass, pyflakes clean, and the frozen build records
and decodes both formats.
